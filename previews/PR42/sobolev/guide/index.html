Sobolev supervision: package guide

L2OSobolev (in lib/L2OSobolev of this repository) adds derivative supervision to any L2OCore method whose proxy predicts primal variables. The theory, assumptions and claims are on the theory page; a runnable example is Sobolev-regularized proxy for a parametric QP.

Getting started

using L2OCore, L2OSobolev, JuMP, HiGHS, DiffOpt, Lux

problem = ParametricProblem(model)            # JuMP model with MOI.Parameter
method  = SobolevRegularized(SupervisedMSE();  # any primal / primal-dual method
                             weight = 1.0,
                             mask = RandomMask(0.1),
                             directions = FullJacobian(),
                             backend = LuxNestedAD())
pipe = L2OPipeline(problem, method)
data = generate_data(pipe; sampler, n = 1000, optimizer = HiGHS.Optimizer)
# in the training loop (sm = StatefulLuxLayer of the proxy):
ℓ = loss(pipe, X, sm(X); targets = batch, proxy = sm)

Labels are optional in the data layer: L2ODataset.derivatives is nothing unless an oracle filled it, and datasets with labels work unchanged with any other method. label_errors checks labels against finite differences of the solver and flags degenerate samples.

Machine-learning frameworks and nested AD

The Sobolev term differentiates the proxy with respect to its inputs inside a loss that is then differentiated with respect to the weights. Measured behaviour (see the design page for the full matrix and dev/nested_ad_matrix.jl):

proxybackendouter ADstatus
Lux StatefulLuxLayerLuxNestedAD()Zygoteexact; tested (SobolevGradientCorrect)
any callable (Lux, Flux, function)CentralDifferences()Zygote (or any AD)$O(h^2)$ approximation of the inner derivative; tested
completion layer around any proxyCentralDifferences(), through_completion = trueZygotetested
Lux layer wrapped in a closureLuxNestedAD()Zygotefails (Lux's rules need the layer itself): use CentralDifferences()
anyForwardDiff inside a Zygote lossZygotesilently wrong (nothing gradients): never do this

Recommendation: Lux + LuxNestedAD() when derivatives must be exact; CentralDifferences() for Flux proxies (e.g. with train_flux! from LearningToOptimize, which already passes proxy = model) and for derivatives through completion layers.

GPUs

  • sobolev_loss, the masks and CentralDifferences use only broadcasts, reshapes and reductions; masks and directions are copied to the array type of the inputs (similar + copyto!), so they run on GPU arrays without scalar indexing.
  • LuxNestedAD uses Lux's helpers, which support GPU devices.
  • Label generation with DiffOpt runs on the CPU, one instance at a time. A GPU oracle (batched KKT solves for ExaModels/MadNLP problems) plugs in through the oracle extension point below.

Extension points

Everything is extended by dispatch on abstract types.

A new mask (e.g. structure-aware masking):

struct TopRowsMask <: L2OSobolev.AbstractDerivativeMask
    rows::Vector{Int}
end
function L2OSobolev.sample_mask(m::TopRowsMask, rng, dims::Dims)
    M = falses(dims)
    M[m.rows, :] .= true
    return Array{Bool}(M)
end

A new backend (e.g. another nested-AD system): subtype AbstractSobolevBackend and implement proxy_jacobian, proxy_pushforward and proxy_pullback for the map types you support; results must be differentiable by the outer AD.

A new oracle (e.g. GPU or batched solvers): subtype AbstractSensitivityOracle and implement

L2OSobolev.sensitivity_labels(o::MyOracle, problem, inputs, directions; rng)
    -> (; labels, primal, ok)

for the directions you support. generate_data(pipe; oracle = MyOracle(...)) uses it, and the test pattern of test_labels.jl (label_errors against finite differences) applies unchanged.

A new label type: subtype L2OCore.AbstractDerivativeLabels (add subsetting in L2OCore) and add a sobolev_loss method.
